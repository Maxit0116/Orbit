# Orbit 3 分钟比赛演示脚本（Phase 10）

**设备**：A（创建者）+ B（协作者，可选第二台手机或模拟器）  
**场景**：异地过年 · 预算 ¥6000  
**前提**：云函数已部署；`DEMO_MP_APPID` 已配置；设备 A 已登录云开发。

## 0:00–0:30 创建 Workspace

1. 打开 Orbit → 首页「创建 Workspace」
2. 输入（或点示例）：
   > 春节我和家人分散在不同城市，想一起回老家过年。请帮我安排交通、住宿、年货和家庭分工，预算6000元。
3. 确认计划 → 创建 Workspace
4. **展示点**：任务树、预算上限、推荐工具卡

## 0:30–1:15 工具跳转 + 结果回传

**设备 A**

1. 打开「跨城交通」demo 工具 → 同 AppID 跳转到首页（演示跳转）
2. 返回 Orbit → 填写交通结果（如 ¥520/人，12-28 09:00–13:00）
3. 打开「年货采购」→ 手动填写送达时间 **12-29 18:00**
4. 填写「家庭聚餐」结果，聚餐时间 **12-28 18:00**

**展示点**：预算更新、时间线、任务完成需用户确认（非自动完成）

## 1:15–1:45 跨任务 Context（Phase 7）

1. 提交聚餐 + 年货后，风险卡应提示：**年货送达晚于家庭聚餐**
2. 点「查看依据」→ 展示规则与相关事实
3. 点「采纳」或「忽略」→ 写入 `guidance.accepted` / `guidance.dismissed` 事件

**展示点**：两个服务结果汇合后产生新判断（PRD Scene 5）

## 1:45–2:30 协作（Phase 8）

**设备 A**

1. 点右上角「分享」→ 发给设备 B（分享路径含 `inviteToken`）

**设备 B**

1. 从分享卡片进入 → 自动 `joinWorkspace`
2. 看到与 A 相同的任务/预算/成员列表
3. 认领「家庭聚餐」任务

**设备 A**

1. 保持 Workspace 页（5 秒轮询）→ 应看到 B 认领后的负责人变化

**展示点**：微信关系链协作 + 轮询同步（非 Collection.watch）

## 2:30–3:00 收束

演示者总结：

> 微信搜索帮你找到工具，AI 推荐给你答案；Orbit 把工具、结果、进度和人组织成一个共同完成目标的空间。

## 故障备份

| 故障 | 备份 |
|------|------|
| 云函数超时 | 使用 MOCK_MODE 本地演示冲突规则 |
| 跳转失败 | 走「手动记录」路径 |
| 第二设备不可用 | 录屏 B 端加入片段 |
| LLM 不可用 | 规则引擎 guidance 仍可演示 |

## 验收清单

- [ ] Intent → Workspace < 30s
- [ ] 至少 2 类服务结果写入
- [ ] `delivery_after_meal` 冲突展示
- [ ] 分享加入成功
- [ ] 认领任务在 A 端可见（轮询 < 10s）
- [ ] 所有外部数据标注「用户确认」
